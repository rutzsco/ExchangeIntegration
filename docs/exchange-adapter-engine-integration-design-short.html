Exchange Adapter ↔ AI Workflow Engine

Proposal only. Just the Milestone 1 connectivity probe is built, and live access to the customer's Exchange is not yet verified.

1Overview

Invoices arrive as emails in an on-premises Exchange mailbox. A small Windows service, the Exchange Adapter, copies each email's attachments to Azure Blob Storage and tells the cloud AI Workflow Engine about it through Azure Service Bus. The Engine checks the invoice and sends back instructions that the adapter carries out in Exchange: email the sender if the invoice is invalid, and move the message to the Processed folder.

Files in storageMessages carry only IDs and a link, so they stay small (256 KB limit on Standard).
The adapter calls outNothing in Azure connects into the customer network: no inbound firewall rules.
Safe to repeatEach email has a stable ID, so a retry is recognized, not duplicated.
No stored secretsWindows identity for Exchange, Entra ID for Azure. No passwords or keys.

2Architecture

3Email in: Exchange → Blob Storage → Service Bus

  1. Read. On a schedule (for example once a minute) the adapter reads new email from the Inbox through Exchange Web Services (EWS), as the Windows service account. The email stays in the Inbox.
  2. Save. Each attachment goes to Blob Storage in a folder named after the email's messageKey. A small manifest.json (sender, subject, file list) is written last, so its presence means the capture is complete.
  3. Announce. One invoice.received message, which only points at the manifest, goes to Service Bus. Only then does the adapter save its place, so after a crash the email is simply picked up again.
  4. Process. The Engine receives the message, reads the manifest and files from Blob Storage, and validates the invoice.

4Decision back: Engine → Service Bus → Exchange

  1. Command. A valid invoice gets a move. An invalid one gets a reply first, and the move only once the reply's result says it worked. If the Engine cannot decide, it sends nothing and an alert is raised.
  2. Act. The adapter pulls the command and checks it against its own rules (known mailbox, known folder, reply only to the original sender), then carries it out in Exchange. Work already done is skipped.
  3. Report. A succeeded or failed result goes back to the Engine. On a failure the email stays in the Inbox and an alert is raised, so nothing is moved or sent silently.

5Messages

Three small JSON messages cross Service Bus. They carry IDs and links, never email content.

MessageDirectionKey fields
invoice.receivedAdapter → EnginemessageKey, mailbox, receivedUtc, link to manifest.json
exchange.command.reply
exchange.command.move		Engine → AdaptercommandId, messageKey, internetMessageId, mailbox, reply text or target folder
exchange.command.resultAdapter → EnginecommandId, status (succeeded or failed), failure reason

messageKey is a hash of the mailbox and the email's Message-ID. It names the blob folder, is the Service Bus message ID and starts every commandId (for example <messageKey>.reply), so repeats are recognized.

6Further considerations

Topics for the next iteration. Where this version assumes an answer, it says so.

#TopicConsideration
1Prove Exchange accessNot yet run against the customer's Exchange. The probe must succeed as the real service account, with Kerberos or NTLM recorded, before anything here is built.
2Mailbox permissionsThe service account must read the Inbox, move messages and send as the mailbox: Full Access plus Send As (simplest), folder-level rights (narrower) or scoped impersonation.
3FoldersAssumed: one Processed folder for everything handled. Do invalid invoices need their own Invalid folder, or a Review folder for items a person must check?
4Email to the senderAssumed: a reply to the original sender only, from the invoice mailbox. Fixed templates or AI-written text, and who approves them? Never reply to automatic mail, and cap replies to avoid loops.
5Untrusted contentEmail text and attachments are untrusted input to an AI system: they must never choose recipients, folders or commands. Scan for malware; the verdict arrives after upload.
6Azure sign-in, networkManaged identity through Azure Arc, or a certificate; never keys. Can the host reach Azure on TCP 5671 or 443 (WebSockets) without a proxy? Private endpoints need Service Bus Premium.
7Failures, monitoringRetries, dead-letter queues, stuck emails, one adapter or a standby. Crash-test every step and prove a reply is never sent twice. Alert on heartbeat, queue depth and oldest Inbox email.
8Volumes, retentionEmails per day, largest attachment and required speed set polling, size limits and throttling headroom. How long are invoices kept, and is a legal hold needed?
9Running as a serviceWindows Service hosting, restart and deployment, the Active Directory service account (today a console app only), separate dev, test and production resources, a test mailbox.
10Exchange Online laterEWS is being retired in Exchange Online (from 1 Oct 2026); Microsoft says on-premises Exchange Server is not affected. If the mailbox ever moves, Exchange access switches to Microsoft Graph.
